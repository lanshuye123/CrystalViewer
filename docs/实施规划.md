# CrystalViewer MVP 实施规划

> 本文档记录 MVP 阶段的实施计划与关键技术决策，作为《功能需求文档》的落地补充。

## 一、MVP 范围

| 模块 | 内容 | 状态 |
|------|------|------|
| F1 空间群查询与解析 | 编号 / H-M 符号输入、晶系筛选、标准化匹配、无匹配建议、信息卡片 | ✅ 纳入 |
| F2 晶胞 3D 展示 | 晶胞线框（a/b/c 轴配色与标注）、原子球体渲染、等效位置生成 | ✅ 纳入 |
| F3 原子点位表格 | Wyckoff 字母 / 多重度 / 位置对称性 / 代表坐标 / 等效坐标；排序、展开、复制、3D 联动 | ✅ 纳入 |
| F4 3D 交互操作 | OrbitControls（旋转/缩放/平移）、自动旋转、重置视角、坐标拾取 | ✅ 纳入 |
| F5 显示设置 | 晶胞边框、原子标签、原子半径、模型类型、背景颜色、对称元素（基础叠加） | ✅ 纳入 |
| F6 数据导出 | CIF / PNG / CSV 导出 | ⏳ 延后 |

技术栈：Vue 3 (Composition API) + TypeScript + Pinia + Element Plus + Three.js + Vite，包管理器 yarn。

## 二、项目初始化

### 2.1 脚手架

- 使用官方脚手架 `create-vue`，特性开关：`--ts --pinia --vitest --eslint --prettier`。
- 因项目根目录已存在文档等文件，先在临时目录脚手架，再复制进项目根，避免非空目录交互提示。

### 2.2 运行时依赖

- `three`（3D 渲染）
- `element-plus` + `@element-plus/icons-vue`（UI 组件）
- `pinia`（脚手架内置）

## 三、空间群数据集（关键依赖）

230 种空间群的对称操作与 Wyckoff 位置是本项目的核心数据，需一次性生成并作为静态 JSON 打包。

### 3.1 数据来源

- **spglib**：对称操作（旋转矩阵 + 平移向量）、Hall / H-M 符号、晶系。
- **pyxtal**：Wyckoff 位置（字母、多重度、位置对称性、代表坐标、全部等效坐标）。
- 默认晶胞参数：按 7 大晶系分别给出标准化值。

### 3.2 生成方式

生成脚本以隔离环境运行，不污染系统 Python（Python 3.14 过新，pyxtal 依赖在 3.13 有可靠 wheel）：

```bash
uv run --python 3.13 --with pyxtal --with spglib scripts/generate-spacegroups.py
```

### 3.3 输出与加载策略

- 输出目录：`src/data/spacegroups/`，按晶系拆分为 7 个 JSON 文件（三斜、单斜、正交、四方、三方、六方、立方）。
- 索引文件：`src/data/spacegroups-index.json`（编号 ↔ 符号 ↔ 晶系），体积小，直接打包进主 Bundle。
- 通过动态 `import()` 按需加载晶系数据文件（对应需求文档 §6.3）。

### 3.4 数据校验

`scripts/validate-spacegroups.py` 对若干已知空间群交叉校验（如 Pnma 一般位置多重度 8、Fm-3m / Pm-3m / Fd-3m 的 Wyckoff 位置），发现差异即报错。

## 四、应用结构

```
src/
  types/crystal.ts          # SpaceGroupData / SymmetryOperation / WyckoffPosition / AtomSite / DisplaySettings
  lib/
    lattice.ts              # 分数坐标 <-> 笛卡尔坐标变换矩阵、晶胞顶点
    coords.ts               # 解析并求值 "x, y+1/2, -z" 形式的坐标表达式
    symmetry.ts             # 对称操作分类、等效原子生成、归约至 [0,1) 并去重
    spacegroup.ts           # 编号 / H-M 符号标准化与匹配、相似建议、按需加载
  stores/crystal.ts         # Pinia：currentSpaceGroup / currentAtoms / displaySettings / selectedWyckoff
  components/
    SpaceGroupInput.vue     # 空间群输入与解析
    SpaceGroupInfoCard.vue  # 空间群基本信息卡片
    CrystalViewer.vue       # Three.js 3D 场景容器
    DisplaySettings.vue     # 显示参数面板
    AtomTable.vue           # Wyckoff / 原子点位表格
    StatusBar.vue           # 底部状态栏
  App.vue                   # 响应式左右分栏布局（60% / 40%）
```

### 4.1 Three.js 集成要点

- 使用 `toRaw()` / `shallowRef` / `markRaw` 剥离响应式代理，避免与 Three.js 内部对象冲突。
- 通过 `watch` 监听 Pinia 状态变化后手动更新场景，而非让 Three.js 对象进入响应式系统。
- 晶胞线框使用 `LineSegments`，原子使用 `InstancedMesh`，拾取使用 `Raycaster`。

### 4.2 默认示范结构

- 默认以单个虚拟元素在**一般 Wyckoff 位置**生成等效原子，适配全部 230 种空间群。
- 点击表格中某个 Wyckoff 行时，生成并高亮该位置的等效原子（自由变量取代表性数值）。

## 五、测试与验证

- Vitest 单测：坐标表达式解析、晶格变换、等效原子生成与去重（Pnma 多重度 8）、符号匹配、数据集抽查。
- 质量门禁：`yarn lint` → `yarn type-check` → `yarn test:unit` → `yarn build`。

## 六、风险与说明

- pyxtal 的 Wyckoff 字母排序在极少数空间群可能与 International Tables 存在差异，由校验脚本标记并按需修正。
- F5 中的“对称元素显示”MVP 阶段仅提供基础的平面 / 轴叠加指示，非完整 ITA 图示符号。
